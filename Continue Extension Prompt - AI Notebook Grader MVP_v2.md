## EXISTING n8n WORKFLOW (v12)
File: `AI Notebook Grader (v2.27.4-RAG-v12).json`

### Flow:
```
Webhook Trigger → Descarga notebook → Formatea y limpia → Recupera rúbrica → Build Prompt → Evalúa notebook → Formatea salida → Respond to Webhook
```

### Nodes:
1. **Webhook Trigger** — POST `/grader`, expects JSON: `{student_name, filename, github_url}`
2. **Descarga notebook a corregir** — HTTP GET to `raw.githubusercontent.com` (responseFormat: json)
3. **Formatea y limpia notebook** — Code node: strips images, truncates outputs to 800 chars, 15k total limit, classifies task from content (numpy_i vs numpy_ii vs pandas)
4. **Recupera rúbrica** — Code node with EMBEDDED rubrics (numpy_i, numpy_ii). Uses task_key from previous node to select rubric. No file I/O (n8n sandbox limitation).
5. **Build Prompt** — Code node: merges cleaned notebook + rubric + evaluation instructions into final prompt
6. **Evalúa notebook** — HTTP POST to `http://192.168.0.37:8083/v1/chat/completions` (Qwen3.6-MTP-27B on llama.cpp)
7. **Formatea salida evaluación** — Extracts grade (Mal/Regular/Bien/Excepcional → 3/5/7/9), returns markdown_report
8. **Respond to Webhook** — Returns JSON response with the grading report

## RUBRICS

- Common errors detected from historical data

## KEY TECHNICAL DECISIONS MADE
1. **Rubrics embedded in Code node** — n8n sandbox blocks file I/O outside `.n8n-files/`
2. **Task classification by content** — filename/URL unreliable; notebook content used to detect task type
3. **Formatea y limpia runs before RAG** — notebook cleaned first to avoid token bloat
4. **responseFormat: json** on HTTP Request — preserves parsed structure
